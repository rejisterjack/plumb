Self-hosted webhook relay for local development

One deploy. A stable public URL for every webhook.

Plumb forwards Stripe, GitHub, and Twilio webhooks to localhost over a WebSocket tunnel. The URL stays the same across restarts and reconnects — so you stop re-pasting endpoint URLs into provider dashboards.

  • Single Go binary — relay and CLI
  • No database, no accounts
  • MIT, self-hosted

How it works

  1. 1

    Deploy the relay once

    One small always-on service gets a persistent public URL. It stores recent webhook bodies in memory and nothing else.

  2. 2

    Connect from your machine

    plumb connect opens an authenticated WebSocket tunnel and forwards each webhook to a local port — raw body and signature headers intact, so verification still passes.

  3. 3

    Point providers at it

    Copy the printed public URL into Stripe, GitHub, or Twilio once. Reconnects reuse the same path, so the URL never changes.

  4. 4

    Replay what you missed

    Webhooks that arrive while you are rebuilding are buffered. plumb replay re-POSTs them to localhost only — it never calls the provider again.

Install the CLI

One static binary for Linux, macOS, and Windows — amd64 and arm64. No runtime dependencies.

Grab an archive from the latest release, or build it yourself: 

go install github.com/rejisterjack/plumb@latest

Deploy the relay

The repo ships a Dockerfile (and a Railway config). Generate a token, set it on a small container host such as Render, and the public URL stays until you delete the service.

Runs anywhere a container runs — you only need PORT and PLUMB_TOKEN. Free hosts may sleep when idle. 

git clone https://github.com/rejisterjack/plumb
cd plumb
openssl rand -hex 32   # set as PLUMB_TOKEN
# deploy the Dockerfile (Render, Railway, or any container host)

Built for local development

  • Stable URL — silent reconnects reuse the same path and token
  • Per-developer paths on one shared relay, isolated from each other
  • Replay buffer for missed events; live pull even when the CLI is down
  • Terminal log of every request with headers and body
  • Token-gated tunnels; constant-time comparison
  • Unguessable per-path URLs act as the capability for inbound webhooks

What it is not

Not a shared service, not a multi-tenant SaaS, and not a production webhook endpoint. Each team runs its own relay; the replay buffer lives in memory and clears on restart.
